# 沙箱文件管理分析报告

## 🚨 重要发现：存在严重的文件泄漏问题

经过详细的代码分析，发现该判题服务与沙箱服务调用后**存在严重的文件清理问题**。

## 1. 产生的文件类型

### 1.1 沙箱服务端文件
根据沙箱API调用，每次判题会在沙箱服务器产生以下文件：

**编译阶段 (`getFieldId` 函数)**：
```go
CopyOutCached: []string{"a.java"},     // Java编译后的.class文件
CopyOutCached: []string{"main.go"},    // Go源文件缓存
CopyOutCached: []string{"main.py"},    // Python源文件缓存
```

**执行阶段 (`judge` 函数)**：
- 使用编译阶段缓存的FileId
- 每个测试用例执行时产生临时文件
- stdout/stderr输出文件

### 1.2 文件存储位置
- **沙箱服务器**：`localhost:5050` 的文件存储系统
- **本地判题服务**：无本地文件产生（只是HTTP调用）

## 2. 文件清理机制分析

### 2.1 当前清理状态：❌ **完全没有文件清理**

**检索结果**：
- ✅ 项目中有 `pkg/utils/file/file.go` 文件操作工具
- ✅ 有 `Remove()` 函数可以删除文件
- ❌ **沙箱调用代码中完全没有文件清理逻辑**
- ❌ **没有调用沙箱的 `/file/:fileId DELETE` API**

### 2.2 沙箱API支持的清理接口

根据沙箱API文档：
```
/file/:fileId DELETE 删除文件 ID 指定的文件
```

但是**当前代码完全没有使用这个API**！

## 3. 文件泄漏问题详细分析

### 3.1 泄漏场景

**每次判题流程**：
```
1. 编译代码 → 产生FileId (如: "abc123")
2. 执行测试用例1 → 使用FileId "abc123"
3. 执行测试用例2 → 使用FileId "abc123"  
4. ...
5. 执行测试用例N → 使用FileId "abc123"
6. 判题完成 → ❌ FileId "abc123" 永远不会被删除！
```

### 3.2 泄漏规模估算

假设系统运行情况：
- 每天1000次提交
- 每次提交产生1个编译文件
- 平均每个文件10KB

**泄漏速度**：
- 每天：1000 × 10KB = 10MB
- 每月：300MB  
- 每年：3.6GB

**实际可能更严重**，因为：
- Java编译后的.class文件可能更大
- 如果编译失败也会产生临时文件
- 长期运行会导致沙箱服务器磁盘空间耗尽

## 7. 解决方案

### 7.1 立即修复方案
```go
// 添加文件清理函数
func cleanupSandboxFile(fileId string) error {
    if fileId == "" {
        return nil
    }
    
    cfg, _ := utils.LoadConfig("conf/config.yaml")
    sandboxCfg := cfg.GetSandboxConfig()
    
    // 调用沙箱删除API
    deleteUrl := strings.Replace(sandboxCfg.Url, "/run", "/file/"+fileId, 1)
    req, err := http.NewRequest("DELETE", deleteUrl, nil)
    if err != nil {
        return err
    }
    
    client := &http.Client{}
    resp, err := client.Do(req)
    if err != nil {
        return err
    }
    defer resp.Body.Close()
    
    return nil
}
```
